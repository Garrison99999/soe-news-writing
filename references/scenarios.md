# 场景与虚构示例

本文件使用通用稿型和自行编写的虚构材料演示方法，不对应真实单位、人物或会议。

## 不同稿型怎样组织

| 场景 | 可以采用的结构 | 重点 |
|---|---|---|
| 慰问走访 | 活动目的与事实—现场具体行动—交流观点—参会范围 | 用行动和交流体现关心，避免将鼓励口吻套入商务座谈 |
| 产业调研 | 导语议题—现场参观—双方工作基础及观点—协作方向 | 参观内容与议题相关，意向与已达成事项分清 |
| 主管部门专题调研 | 工作情况—具体实践—调研方意见—企业回应 | 讲话强度以记录为据，企业回应承诺不编造 |
| 简短合作座谈 | 导语—双方分别表态—真实共同认识或合作方向—参会范围 | 篇幅简洁，避免为凑共识虚构协议 |
| 专项安全调研 | 现场与问题—具体意见—企业回应—参会范围 | 治理职责和企业责任准确对应 |
| 企业渠道交流消息 | 来访方业务介绍—我方业务基础—双方观点—现场及参会 | 标题和语气按渠道调整，不自动采用宣传性标题 |

## 虚构练习一：职责清单

笔记：某企业与主管部门讨论信息服务协作。部门代表建议各单位把职责列成清单，分清责任，再共同研究衔接办法。

可写：该代表建议细化职责清单、明确责任分工，强化工作衔接，推动信息服务协同。

不能据此写为：会议决定成立联合指挥机构，并已完成责任清单。

经验：从口头话提炼清单、责任与协同有依据；新增组织、决定和完成状态没有依据。

## 虚构练习二：已有事实与未来意向

笔记：甲方已整理服务对象基础信息；乙方希望两个业务系统共享部分信息；双方拟讨论一个服务试点，没有决定时间和责任人。

可先交代已有基础，再写两项合作方向；如保留三项并列，总起句应说明讨论的是工作基础和协作设想。

不能把三项一律称作已落实举措，也不能写成双方已经完成系统对接或确定试点实施计划。

## 虚构练习三：人物观点与会议认识

笔记：企业代表介绍服务进展；来访代表提出技术协作建议；双方都同意应准确管理业务信息，但对系统方案仍需继续研究。

可分别写两位代表的介绍和建议，随后简要概括双方对信息管理的共同认识。系统方案保持在待研究层面。

经验：真实共识可以使用会议表述，但不因此将所有单方建议升级为共同意见。
